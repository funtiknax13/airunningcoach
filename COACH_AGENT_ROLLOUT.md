# Агентный тренер: первый этап перехода

Обновлено 2026-11-16: агентный режим используется в чате всех пользователей,
без переключателя и списка аккаунтов. Генерация планов кнопкой продолжает работать.
Миграций БД нет: новые метаданные хранятся
в существующем JSON `ChatMessage.plan_draft` с `agent_version=1`.

## Деплой и настройки

После коммита всех изменённых и новых файлов push в `master` запускает существующий
workflow деплоя. После успешной пересборки backend все новые сообщения чата идут
агенту. Отдельного включения в `.env` не требуется.

В окружении backend можно ограничить число шагов:

```env
COACH_AGENT_MAX_STEPS=6
```

Прежние `COACH_AGENT_ENABLED` и `COACH_AGENT_USER_IDS`, если остались в старом `.env`,
игнорируются и не могут выключить агента. Подтверждение старых предложений без
`agent_version` сохраняет совместимость. Данные, схемы и история не удаляются.
Откат к старому обработчику требует возврата версии кода и повторного деплоя;
переключателя режима нет.

Нужны действующие `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL` с
поддержкой function calling. Используется тот же клиент SDK, отдельного сервиса
нет. Агент закреплён за DeepSeek в режиме без thinking; текущий failover обычного
чата/аналитики не изменён. Автоматического переключения незавершённой агентной
операции на старый генератор нет.

## Контракт инструментов

`backend/app/services/coach_agent.py` содержит разрешённый реестр:

- `get_training_summary`: профиль, цели, зоны, статистика и последние пробежки.
- `get_calendar`: календарная неделя Пн–Вс, фактические пробежки, заблокированные
  даты, ограничения и последний актуальный обсуждаемый вариант этой недели.
- `get_activity_details`: детали только своей активности; GPS-трек не передаётся.
- `preview_calendar_change`: все редактируемые даты выбранной недели, отрезки
  занятий, договорённости о частоте, минимуме км, дате длинной и днях отдыха.

Аргументы валидируются Pydantic; неизвестные поля, инструменты, чужие ID,
повторяющиеся/прошедшие/заблокированные даты отклоняются. Модель не получает
возможности выбрать user_id, исполнять код или сохранять тренировки.

Первый горизонт — одна полная календарная неделя: текущая либо одна из следующих
четырёх. Для изменяемых дат нужны дистанции, известные напрямую или вычисленные
по зонам; непроверяемые по объёму занятия пока отклоняются. Существующая программа
по времени для новичков доступна прежней генерацией, она не переписана.

## Проверки и сохранение

Проверяется вся неделя с фактом, а не только оставшиеся дни: частота, недельный
потолок, дистанция занятия, интенсивность, соседство нагрузочных дней (включая
границы недели), дата длинной, минимум км и отдых. Используются текущие формулы
`planner` как начальная политика, не новая доказанная тренировочная методика.
Скрытого изменения результата/обрезания дистанций нет — конфликт возвращается
модели. Числа и описание отрезков формирует существующий `plan_format` по `zones`.

Успешный ответ о готовности формируется кодом по проверенному предложению.
При отказе проверки ответ не может обещать готовое предложение. Отдельное
подтверждение повторно проверяет ограничения и снимок профиля/истории/целей/
предпочтений/соседнего календаря. Изменение данных или наступление нового дня
возвращает 409. Выполненные и прошедшие даты не перезаписываются. Применение и
отметка подтверждения коммитятся одной транзакцией. Новое предложение той же
недели помечает прежнее как заменённое. Повторное подтверждение отклоняется.

Квота `chat` — один пользовательский ход, внутренние tool calls её не расходуют.
Квота `plan` списывается при публикации первого валидного предложения. Правки
неподтверждённого предложения той же недели в тот же день на неизменной базе
не списывают новый план. После применения, изменения базы или смены дня начинается
новая операция. Квота и публикация коммитятся вместе; ошибки провайдера возвращают
конкретное списание чата. Число model steps — максимум 8 (по умолчанию 6), tool calls —
12, общий срок ожидания модели в ходе — 90 секунд. Токены каждого шага пишутся
в серверный лог без текста сообщений и ключей.

Пользовательские условия в этом этапе привязаны к обсуждаемому предложению недели.
Новый инструмент долговременной памяти, месячный агентный план, устойчивый этап
подготовки и отдельная квота AI-правок не добавлены. Профиль и старые предпочтения
читаются существующими сервисами. Кнопка генерации месяца остаётся во вкладке
«План»; рядом с агентным предложением она скрыта, чтобы не подтверждать другое
расписание вместо показанного.

## Проверка

```powershell
cd backend
..\.venv\Scripts\python.exe -m pytest -q
cd ../frontend-v2
npm run build
```

Тесты `test_coach_agent.py` подменяют только транспорт модели. Инструменты,
валидация, HTTP, квоты, сохранение и отображаемая JSON-структура — реальные.
БД — временная SQLite, API не вызывается. Тесты обычной генерации, зон, импорта,
предпочтений и старых предложений сохраняются.

Живой smoke test делать сначала на тестовом аккаунте: прочитать неделю,
согласовать длинную и минимум км, исправить предложение, подтвердить, проверить
календарь, загрузить пробежку и убедиться, что устаревшее предложение отклоняется.
Сравнить токены/задержку/число уточнений по нескольким реальным диалогам.
PostgreSQL-конкурентность и реальное качество DeepSeek не подтверждаются SQLite
и scripted-model тестами; их нужно проверять отдельно. Режим для всех пользователей
не означает, что эти проверки уже выполнены.
