# Инструкция: как проверить новую систему планов локально

Всё описанное сделано **только в рабочей папке, без коммитов и без пуша**; прод и боевые ключи не затронуты. Ниже — от быстрого (тесты) к полному (руками в браузере, потом с реальным ИИ).

## 0. Что изменилось (для ориентира)

- Тренировка в плане теперь — список **отрезков с зонами** (`easy/tempo/...`), а не текст с числами. Темп, пульс, средний темп, дистанцию и время считает **код** по зонам пользователя (`backend/app/services/zones.py`, `plan_format.py`). ИИ выбирает структуру и зоны, числа не пишет.
- Если ИИ недоступен или ответил невалидно — план строит **алгоритм** (`planner.py`) с пометкой «по правилам, без ИИ». Шаблонных планов больше нет. Для новичков программа «бег/ходьба по времени» строится алгоритмом по замыслу (без пометки о сбое).
- Зоны считаются из: недавнего результата → истории пробежек → «моего лёгкого темпа» → иначе «по ощущениям». Пульс: профиль (макс./покоя, Карвонен) → история → оценка по возрасту.
- Новые поля профиля (пульс, лёгкий темп, недавний результат), поле «усилие» у пробежки, оценка «легко/нормально/тяжело» после тренировки, окно «Нужны данные» перед генерацией.
- Чат: пожелания «хочу N раз в неделю / длинную в воскресенье» сохраняются и действуют, пока пользователь сам не изменит число дней в профиле; в конце ответа тренер советует обновить профиль.
- Число тренировочных дней (`recovery` тоже день) гарантируется кодом.
- Фронтенд: график отрезков, средний темп считается кодом, пометки об источнике/точности плана, окно данных, профиль/онбординг, дашборд.
- Миграция БД `0018_plan_zones` (только добавляющая, обратимая).

## 1. Быстрая проверка без сервера (2 минуты)

Терминал в корне проекта (PowerShell):

```powershell
cd backend
..\.venv\Scripts\python.exe -m pytest tests -q -W ignore
```
Ожидание: все тесты зелёные (сейчас 144). (Если pytest не установлен: `..\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt`.)

Тесты по файлам: `test_zones.py` (зоны темпа/пульса), `test_plan_format.py` (формат отрезков, средний темп), `test_planner.py` (алгоритм, ровно N дней, разгрузка, новичок, потолки), `test_plan_ai.py` (ИИ с подставным ответом: повтор, откат, целиком-или-ничего для месяца), `test_chat_prefs.py` (пожелания из чата), `test_api_plans.py` (HTTP-сценарии: профиль, план, возврат попытки, самокалибровка, чат, RPE), `test_plan_job.py` (фоновый месяц).

Фронтенд:
```powershell
cd ..\frontend-v2
npx vue-tsc -b          # проверка типов, без вывода = успех
npm run build           # сборка
```

## 2. Поднять локальное окружение

Нужен Docker и **Git Bash** (в PowerShell пустые переменные окружения удаляются и не перебивают `backend/.env`, поэтому окружение задаём в Git Bash).

**Терминал 1 — база и бэкенд (Git Bash, из корня проекта):**
```bash
docker run -d --name plan-pg -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=dev -p 5544:5432 postgres:16-alpine
cd backend
source scripts/dev_env.sh                  # своя БД + все внешние ключи пустые
../.venv/Scripts/python.exe -m alembic upgrade head        # включая 0018_plan_zones
../.venv/Scripts/python.exe scripts/dev_seed.py            # 3 тестовых пользователя
../.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000
```

**Терминал 2 — фронтенд (любой терминал):**
```powershell
cd frontend-v2
npm run dev            # http://localhost:5173, /api проксируется на :8000
```
Открывайте **http://localhost:5173**. (Можно и без dev-сервера: `npm run build`, затем http://localhost:8000. В консоли браузера будет ошибка про `schema.js` — это особенность запуска через бэкенд, в проде этот файл отдаёт nginx.)

Пользователи (пароль у всех `Demo12345!`, капча выключена):

| Email | Кто | Для чего |
|---|---|---|
| `runner@example.com` | бегун с историей (~7:30/км), Premium | план с реальными зонами, месяц |
| `nodata@example.com` | без данных о темпе | окно «Нужны данные», самокалибровка |
| `newbie@example.com` | новичок «0 км» | программа бег/ходьба |
| `fresh@example.com` | новый аккаунт **без пройденного онбординга** | онбординг (в т.ч. необязательные темп и пульс на 4-м шаге) |

Пересоздать только нового пользователя, не трогая остальных: `python scripts/dev_seed.py fresh`.
Сбросить всё в исходное: снова `python scripts/dev_seed.py` (пересоздаёт этих пользователей и их данные; планы удалятся вместе с пользователем).

## 3. Чек-лист руками (в браузере)

Без ключей ИИ бэкенд честно работает «без ИИ»: планы строит алгоритм с пометкой. Это и есть проверка запасного пути.

**A. `runner` — план с зонами и график отрезков**
1. Вход → «План» → «Создать план» (неделя). Окна данных нет (история есть).
2. Сверху недели — пометка «План составлен по правилам, без ИИ…» и кнопка «Пересоздать с ИИ».
3. Листайте на следующую неделю стрелкой: там темповая/интервальная. Проверьте карточку: график отрезков, диапазон темпа «быстрее–медленнее», пульс, комментарий; плашка `≈ X:XX/км` — средний темп с разминкой и заминкой (**не** расходится с отрезками — это исправленный баг «5:24»).
4. Тренировок ровно столько, сколько в профиле (4). Легкие/длинная — одна строка без графика.
5. «Месяц» → «Создать план» → индикатор «План готовится…» → 28 дней, в каждой календарной неделе ≤ 4 тренировок, одна неделя (каждая 4-я) легче.

**B. `nodata` — окно данных и самокалибровка**
1. «Создать план» → открывается окно «Чтобы план подходил именно вам» (три вкладки: пробежка / результат / мой темп).
2. Вкладка «Мой темп»: `7:50` → «Сохранить и создать план». Появляются диапазоны темпа (числа), пометка «Оценка: темпы и пульс уточнятся…».
3. Не вводя ничего («Пропустить…») план строится без числовых темпов, чипы «по ощущениям».
4. Самокалибровка: у пользователя без темпа добавьте 3 пробежки («Тренировки» → «Добавить», разные даты, ~5 км, ~7:30). Вернитесь в «План» — числа темпа появились **без пересоздания плана**.
5. Вкладка «Результат» (например 5 км за 32:15) тоже даёт зоны; «Пробежка» умеет загрузить файл GPX/FIT и спросить «как вы бежали».

**C. `newbie` — начинающий**
1. «Создать план» → окно → «Пропустить…». План: «ходьба 5 мин, N×(бег…, ходьба…), ходьба 5 мин», время без километров, пометка «Стартовая программа для начинающих» (это не «сбой ИИ»).
2. Число дней не больше 4 даже при выборе «5+».

**D. Профиль → «Тренировки»**
1. Новые поля: максимальный пульс, пульс покоя, лёгкий темп (`7:30`), недавний результат. Неверный формат (`7-30`, время без дистанции) даёт понятную ошибку. Пульс/темп вне диапазона отклоняется сервером (`422`).
2. Сохраните лёгкий темп — числа темпа в будущих тренировках пересчитываются. Выполненные тренировки не меняются (хранят снимок).
3. Онбординг (новый пользователь): на 4-м шаге — необязательные «комфортный темп» и «максимальный пульс».

**E. Чат и пожелания** (ИИ выключен → ответ «недоступен», но пожелание и подсказка работают)
1. `runner`, чат: «Хочу тренироваться 5 раз в неделю» → внизу ответа подсказка «…в профиле сейчас указано 4 дн. … лучше изменить на 5 (Профиль → Тренировки)». Сообщение об ошибке ИИ не сохраняется в историю и попытка чата не списывается.
2. Затем в «Плане» «Создать план» → 5–6 тренировок в неделю (пожелание действует).
3. Профиль → «Тренировки» → измените число дней (например, на 3) → сохраните → следующий план снова по профилю.
4. Вопросы («Можно ли 5 раз?»), отрицания («Не хочу 5 раз…») и факты («Обычно бегаю 3 раза») пожеланием **не считаются** (покрыто тестами).

**F. Оценка тренировки**
Для `runner`: «План» → «Начать с сегодня» → «Создать план». Добавьте пробежку на сегодня примерно под сегодняшнюю тренировку («Тренировки» → «Добавить») → в «Плане» «Отметить» → «Выполнено». Под карточкой появятся «Легко / Нормально / Тяжело»; выбор запоминается (следующий план учтёт две «тяжело» подряд снижением нагрузки).

**G. Возврат попытки**
У Basic лимит «1 план в день», но пока план строит алгоритм (ИИ не тратился), генерировать можно сколько угодно — попытка возвращается.

**H. Проверка выполнения тренировки относительно плана**

Как это работает (`backend/app/services/workout_verification.py`): статус ставится автоматически при добавлении, импорте или правке пробежки (по дате тренировки в вашем часовом поясе) и вручную кнопкой «Отметить» (берётся лучшая пробежка в пределах ±1 дня). Сравниваются относительные отклонения факта от плана: **≤ 7% — «Выполнено»**, **7–30% — «≈ Близко»**, **> 30% — «Не подтверждена»**. Что сверяется: дистанция; средний темп (плановый — тот, что считает код по отрезкам); для тренировок «по времени» (программа новичка) — длительность; для интервалов при импорте GPX/FIT ещё число повторов и их темп (для пробежки, введённой вручную, разметки повторов нет, сверяются только объём и средний темп).

Что проверить руками (`runner`, «План» → «Начать с сегодня» → «Создать план»; затем «Тренировки» → «Добавить» пробежку на дату тренировки и посмотрите статус в «Плане»; правка той же пробежки пересчитывает статус):

| Тренировка (пример) | Пробежка | Ожидаемый статус |
|---|---|---|
| Лёгкая 3.5 км, план 7:16–8:06/км | 3.5 км, 7:40 | Выполнено |
| то же | 3.0 км, 7:40 (на 14% короче) | ≈ Близко |
| то же | 1.7 км, 7:40 (вдвое короче) | Не подтверждена |
| то же | 3.5 км, 6:30 (слишком быстро) | ≈ Близко |
| то же | 3.5 км, 4:30 (на пределе) | Не подтверждена |
| Темповая 6 км (средний ≈ 6:45) | 6 км в среднем 6:45 | Выполнено |
| то же | 6 км вся в лёгком темпе (7:40) | ≈ Близко |
| то же | 3 км | Не подтверждена |
| Интервалы (5×400 м), пробежка из GPX/FIT с 5 повторами | 5 повторов | Выполнено |
| то же, но 2 повтора | 2 повтора | Не подтверждена |
| `newbie`: 30 мин бег/ходьба | 30 мин | Выполнено |
| то же | 26 мин | ≈ Близко (раньше засчитывалось как «Выполнено») |
| то же | 10 мин | Не подтверждена (раньше «Выполнено») |
| Любая тренировка, кнопка «Отметить» без пробежки | — | Не подтверждена |

Все эти случаи закреплены тестами: `backend/tests/test_verification.py`. Известное поведение: если пробежку **удалить**, статус тренировки не сбрасывается сам (снять отметку можно кнопкой «↺» на карточке).

## 4. Проверка с реальным ИИ (когда будут dev-ключи)

Делайте в **том же Git Bash терминале**, где выполнен `source scripts/dev_env.sh` (ключи задаются только в этой сессии, в файлы не пишутся):

```bash
export DEEPSEEK_API_KEY="..."      # и/или GROQ_API_KEY="..."
# или Gemini (третий провайдер, OpenAI-совместимый эндпоинт Google):
export GEMINI_API_KEY="..."
# необязательно: GEMINI_MODEL (по умолчанию gemini-3.6-flash), GEMINI_REASONING_EFFORT (по умолчанию low;
# без ограничения «рассуждение» съедает токены и JSON обрывается)
../.venv/Scripts/python.exe scripts/ai_plan_check.py            # ~2 недельных генерации (runner + nodata)
../.venv/Scripts/python.exe scripts/ai_plan_check.py --chat     # + один ответ тренера
```
Ожидание: `source=ai reason=None`, число дней с нагрузкой = профилю, объём в разумных пределах, комментарии по тренировкам, в чате тренер называет темпы/пульс только из блока «ЗОНЫ». `source=rules reason=invalid|ai_failed` значит, что ИИ не дал пригодный план и сработал откат (штатно; причины — в логе бэкенда). Скрипт ничего не сохраняет в БД.

Затем перезапустите uvicorn в этом же терминале (с ключами) и повторите пункты A и B в браузере: у планов от ИИ **нет** пометки «по правилам», а темпы/пульс всё равно считаются кодом.
Бесплатный тариф Gemini: около 5 запросов в минуту на модель (429) и периодические 503 «высокая нагрузка» — план тогда строит алгоритм (`source=rules reason=ai_failed`), это штатно; повторите через минуту. Порядок провайдеров: Groq → DeepSeek → Gemini (в dev с одним ключом он единственный).
Расход: одна недельная генерация — 1 запрос (при невалидном ответе +1 повтор), месячный — 2 запроса на куски по 14 дней. Groq на бесплатном тарифе ограничен 8000 токенов/мин (возможны 413 — тогда сработает DeepSeek/откат).

## 6. Что не сделано / на что обратить внимание

- **Ничего не закоммичено.** Новые файлы: `backend/app/services/{zones,plan_format,planner,plan_ai,plan_service,chat_prefs}.py`, миграция `0018_plan_zones.py`, `backend/tests/`, `backend/scripts/{dev_seed,dev_env,ai_plan_check}`, `frontend-v2/src/components/training/`, `frontend-v2/src/utils/{plan,time}.ts`; изменены роутеры/схемы/модели/`ai_agent.py`, страницы плана/профиля/онбординга/дашборда, i18n. Мобильное приложение не трогалось. CI не менялся (шаг с тестами не добавлен).
- **Формулы и пороги — ориентиры, их нужно показать тренеру** (`zones.py`, `planner.py`: коэффициенты зон, +8%/нед, разгрузка ×0.75 каждую 4-ю неделю, программа бег/ходьба, потолки длинной по уровню). Формулировки про здоровье в профиле нейтральные — прочитайте и поправьте.
- Не реализовано: сравнение «план против факта» **по отрезкам** (сейчас сравнение по общей дистанции/среднему темпу, для интервалов — по числу повторов и темпу), диалоговый онбординг с итоговой сводкой пожеланий, профильное поле «день длинной» (сейчас только из чата), шаг тестов в CI.
- Реальный ИИ проверен только на подставных ответах (тесты) — живой прогон по п. 4 остаётся за вами (нужны dev-ключи).
- Перед выкладкой на прод: миграция применится автоматически при старте контейнера (`entrypoint.sh`); она добавляет только nullable-колонки и таблицу `plan_preferences`, старые планы и пользователи продолжают работать.
